# 设计说明

## 模块划分

程序分成四层：

1. `Rational` 负责分数约分、四则运算、比较和带分数格式化。
2. `Expression`、`NumberExpression`、`BinaryExpression` 构成表达式树；每个节点同时保存表达式值和等价键。
3. `ExpressionGenerator` 随机生成树并检查题目约束，`ExpressionKey` 负责交换等价去重。
4. `Main` 解析命令行；`ExerciseFiles` 读写文件；`ExpressionParser` 与 `AnswerGrader` 完成附加的批改功能。

主要调用关系如下：

```text
Main
├── ExpressionGenerator
│   ├── NumberExpression / BinaryExpression
│   ├── Rational
│   └── ExpressionKey
├── ExerciseFiles
└── AnswerGrader
    ├── ExerciseFiles
    └── ExpressionParser
        └── BinaryExpression / Rational
```

## 生成过程

生成一题时先随机选择 1 到 3 个运算符，再把剩余运算符数量分给左右子树。叶子可以是自然数、真分数或带分数，所有叶子都小于 `-r` 指定的范围。

建立运算节点时按以下规则处理：

- 加法、乘法可以直接建立；
- 减法发现左值小于右值时交换左右子树，保证该节点结果不为负数；
- 除法排除 0 和相等的值，并让较小的正数作为被除数，最后再次确认结果是严格大于 0、小于 1 的真分数；
- 子树本身也按同样规则生成，所以每一个中间步骤都满足约束。

候选题生成后，把 `ExpressionKey` 放入集合。只有集合中不存在同样的键，题目才会被接受。

## 去重规则

`ExpressionKey.BinaryKey` 保存运算符和两个子键。比较加法或乘法时，同时接受 `left/right` 与 `right/left` 两种顺序；比较减法或除法时只接受原顺序。子键仍按同一规则递归比较。

因此：

- `23 + 45` 和 `45 + 23` 会得到相同等价键；
- `3 + (2 + 1)` 和 `(1 + 2) + 3` 会得到相同等价键；
- `(1 + 2) + 3` 与 `(3 + 2) + 1` 的树形对应不上，仍会视为两道不同题，和题目示例一致。

这里没有把整棵加法树“拍平”，因为题目要求的只是有限次交换左右子表达式，并没有要求应用结合律重新分组。

## 精确计算与显示

如果用 `double`，`1/6 + 1/8` 之类的运算会出现二进制浮点误差。`Rational` 改用任意长度整数保存分子和分母，构造时除以最大公约数，所以答案始终是最简分数。显示时：

- 整数显示为 `2`；
- 真分数显示为 `3/5`；
- 大于 1 的非整数显示为 `2’3/8`。

表达式输出时根据运算优先级补必要括号，避免树的含义在文本中发生改变。

## 批改流程

批改模式不直接相信 `Answers.txt` 的原始答案。程序逐行解析 `Exercises.txt`，按括号、乘除、加减的优先级重新计算正确答案，再和提交答案约分后比较。缺失或格式错误的答案直接记为 Wrong，最终按题号生成 `Grade.txt`。
